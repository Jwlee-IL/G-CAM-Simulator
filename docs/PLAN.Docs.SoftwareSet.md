# PLAN.Docs.SoftwareSet — GCAM Studio software documents as a demonstration set (Word + PDF)

Scope: TODO-53. Turn the existing GCAM Studio verification Markdown into a **set of formatted documents** (Word and PDF,
English), generated by a script from the Markdown, so the repository shows what its software life-cycle records look like
as documents. Purpose (author, 2026-10-20): **a credible-looking demo — not a submission** ("문서를 딱히 제출할 생각은
없어. 그냥 그럴싸한 데모용이야"). Every document says so on its cover.

Status: planned 2026-10-20; waiting for the implementer's review.

## Page furniture (added; the body text is the source, not reworded)
- Cover: set name, document ID, title, revision (`<edition id>`), date, source commit hash, and a banner
  "Demonstration document — generated from the repository's Markdown; not a regulatory submission."
- Document control table: revision history drawn from `git log` of each source file (first commit, last commit, short
  hashes) — no invented approvals; the approval block says "not applicable (demonstration)".
- Table of contents (headings 1–2), running header (ID · title · revision), footer (page *n* of *N*).
- Tables, fenced code, inline code, bold / italic, lists, internal links.
- Links: a link to another document **in the set** becomes "GCAM-SW-xxx §n"; any other link (AGENTS.*, PLAN.*, source
  files) becomes plain text with no URL; no link leaves the set.

## Generator
- `samples/docs/software_set.py` (`generate --out <dir>`, `check --edition <dir>`), standard library only, like the manual
  writers. Reuse what fits from `samples/manual/manual_formats.py` (deflate, OOXML package writer); extend the parser for
  tables and fenced code rather than forking it, without changing the manual's output (its `check --all` must still pass).
- **Word:** hand-written OOXML (styles, tables, TOC field, header/footer with PAGE / NUMPAGES fields).
- **PDF:** HTML with print CSS rendered by **headless Microsoft Edge** (`--headless --print-to-pdf`, no window, no focus;
  Chromium page-margin boxes for header / footer / page numbers). Reason: the manual's own PDF writer draws text from a
  committed glyph subset (105 characters), and the Studio documents use about 40 characters outside it; extending the
  subset needs the font files (a download) and a table layout engine — out of proportion for a demo. The Edge version is
  recorded; PDF bytes are not expected to be reproducible.
- Output: `docs/deliverables/software/<edition>/` — the four rendered documents × (docx, pdf), the index, and a
  `generation-record.json` (source paths + SHA-256, commit, generator hash, Edge version, page counts).
- Never writes outside `--out`; never touches the source Markdown.

## Checks (proportionate)
- `check`: every source heading appears in the rendered documents' text (DOCX XML and PDF text layer) in order; no link
  target outside the set survives; the cover banner and IDs are present; the record's source hashes match the tree (else
  "stale edition").
- Unit tests (`unittest`, catalogued per the test-records rules): table / code / link parsing, link rewriting, header
  furniture, the manual's writer unchanged.
- One look at two rendered pages per document by the planner (PNG of the PDF pages) before the commit.

## Not in this task
Product-side `VV.Gcam.*` documents, translation, approvals or signatures, changes to the source Markdown's content, the
test catalog in full, any desktop step (Edge headless opens no window; it is announced to the other sessions like any
batch).

## Done when
The set is generated and committed as one edition, `check` passes, the unit tests pass, the manual's `check --all` still
passes, and the planner's page review shows no clipped tables or missing furniture.
